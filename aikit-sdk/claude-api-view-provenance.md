## Actual native API finding

We inspected declarations generated by the installed, checksum-pinned Claude
2.1.308, following the official [version-specific types procedure](https://code.claude.com/docs/en/plugins/mods/create#get-type-definitions-for-your-version).
The public repository declaration was labelled 2.1.277 and was not substituted
for the installed version. Installed declarations SHA-256:
`3c29d70e7f113f2409db12c3db20dd8385296c46aaf26984d00e5ecacd37c2c0`.
The complete vendor declaration stays in local evidence, not this repository.

`session.messages({as:'api'})` is itself hookable. An ordinary interactive native
command invoked it with a separate append-tier diagnostic mod. Native core
returned an empty API view; the competing mod appended a fabricated user message.
The API caller received the fabricated view, while the genuine settled core trace
retained the empty result. Control without the competitor returned the empty
view. No model prompt/request was submitted in this command-only probe.

Thus trusting the plain API array was an **AIKit implementation gap**. Existing
native trace APIs can detect this particular alteration; a new provider API is
not needed for that check. See [hook chaining](https://code.claude.com/docs/en/plugins/mods/events)
and the [mods API](https://code.claude.com/docs/en/plugins/mods/api).

## Implemented guard

The generated 2.1.308 input observer scopes one pending API read to its existing
plugin identity and main-session arguments. Its `session.messages` handler:

- delegates exactly once and requires one genuine engine/core settled trace;
- requires the exact main-session API-read arguments and a returned/passed result;
- bounds both API arrays at 4 MiB and compares their canonical complete values;
- retains the matching value only for this pending read.

The caller compares its final unwrapped API array with that scoped value again.
This catches downstream alteration, upstream alteration after the observer,
short-circuited core reads and skipped observers. Missing/changed evidence stops
the message pump and cannot prepare an input candidate, substitute a later step
or resend the frozen review. Unrelated/subagent reads delegate normally.

The existing append record remains version one when input preparation is refused;
successful input preparation retains the existing version-two contract. No
acknowledgement, consumption, delivery state or readiness capability is promoted.
