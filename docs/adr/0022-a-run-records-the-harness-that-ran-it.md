# A run records the harness that ran it

## Status

accepted

## Context

A trace is read to answer a question the run itself cannot: *why* did the agent do this. The closed loop described in "Agentic Harness Engineering" (arXiv 2604.25850) evaluates a harness on a benchmark, distils the rollout traces into root-cause reports, lets a meta-agent edit the harness — system prompt, tool descriptions, tool code, middleware — with a prediction per edit, and verifies each prediction on the next evaluation. Every step of that loop ties a behaviour in the trace to a specific piece of the harness that was in effect, so its canonical trace carries the system prompt, the tool definitions, each assistant turn with its tool calls and their latencies, and the middleware hooks that fired.

aikit's per-trial `trace.jsonl` ([ADR 0020](0020-eval-artifacts-are-an-additive-only-contract.md)) already records ordered text, tool-use and tool-result frames correlated by `call_id`, token usage with the cache and reasoning split, and a terminal frame with the agent's own outcome and the vendor-reported cost. Measured against the loop's needs, four things are missing, and reading the code corrected the analysis in three places.

**No harness snapshot.** Nothing in the stream says which system prompt or which tool definitions the model saw. For the in-process agent both are assembled in `loop_runner::build_system_instructions` and `build_tools` and then discarded once the request is built. Claude Code does not expose its prompt at all; pi over RPC and the in-process agent could.

**Interventions have no general frame.** `AikitContextCompressed` is the one frame that records the harness acting on the run, and on `trace.jsonl` it does not even survive: `agent_events_to_trace` models neither it nor any other `Aikit*` frame, so an in-process run's compression, step boundaries and final text all land as `unknown` with a Rust `Debug` string. The correction here is larger than the gap: the vocabulary has `AikitSubagentSpawn` and `AikitSubagentResult`, but nothing produces them. `SpawnSubagentTool` runs the nested loop through the collecting entry point and drops every nested event, so a sub-agent's tool calls are invisible. And the in-process agent has no tool-approval path: `RunOptions::auto_approve` and `yolo` are no-ops there, and the only refusals are the unknown-tool arm of `execute_tool`, the persona allow/deny filter applied at construction, and path checks inside individual tools. `BackendCapabilities` has declared `hooks` and `context_compression` flags for some time without any frame for them to point at, and pi's `compaction_end` is decoded into a status message — an intervention recorded as prose.

**No per-call duration.** `aikit-session-capture::ToolEvent` carries `started_at_ms` and `duration_ms` for transcripts read off disk; the live vocabulary carries neither. No external decoder reads a timestamp today: claude's `duration_ms` is on the run-level `result` line, pi's `tool_execution_end` has none, and opencode's parts carry `time.start`/`time.end` but its decoder emits no typed tool frames yet. Long-step detection is one of the signals the reference loop keys on, and the in-process agent is the one backend that executes the tool itself and can measure honestly.

**Reasoning is not attached to a turn.** The in-process agent never emits reasoning at all — its OpenAI-compatible stream has no reasoning variant — and external backends emit `kind: reasoning` messages the trace does not group. This one is left alone: it falls out of turn grouping, which is a separate change, and nothing here makes it harder.

## Decision

**A `HarnessSnapshot` frame, emitted once at run start, behind `RunOptions::capture_harness`.** The flag is declared the way `emit_raw_transport` is — a `bool` on `RunOptions`, a `with_capture_harness` builder, `false` by default — and `CaseRunOptions` gains the same field, `false` at every existing construction site, so an eval can ask for it end to end. The frame carries `backend`, `model`, `system_prompt`, `tools` (name, description, input schema), `skills` and `hooks`. It is opt-in for three reasons that do not go away: the prompt plus every tool schema is written once per trial and can be large; persona prompts and `AGENTS.md` contents are the user's and may be sensitive; and a system prompt that lists the skill catalogue would land in the check haystack, which spec 015 closed against exactly that false pass. The flag gates the snapshot only. Hook frames and tool durations are the run's own events, small, and always on.

**A generic `Hook` frame: `phase`, `hook_name`, `action`, optional `payload`.** `phase` is where in the loop the hook ran (`run_start`, `before_model`, `after_model`, `before_tool`, `after_tool`, `run_end`); `action` is what it did (`injected`, `blocked`, `modified`, `observed`). `AikitContextCompressed` keeps its name and its shape, is not re-emitted as a `Hook` in the stream, and the eval converter folds it into a `hook` line with `hook_name: "context_compression"` and `action: "modified"`. The rule is **one intervention, one frame in each vocabulary**: a specific frame that already records an intervention is never doubled by a generic one. The in-process agent emits `tool_dispatch`/`blocked` when the model calls a tool that is not in its set, and `persona_tool_policy`/`modified` at run start when a persona's allow or deny list removed tools. No external backend emits a `Hook` yet; pi's `compaction_end` is the first candidate, and claude's hook events the second.

**`duration_ms` and `started_at_ms` as optional fields on every tool-result frame**: `Decoded::ToolResult`, `AgentEventPayload::ToolResult`, `AgentEventPayload::AikitToolResult` and `TracePayload::ToolResult`. The in-process agent measures both around its own `execute_tool`. Every external backend leaves them absent today, because none of their decoders sees a per-call timestamp. The SDK does **not** stamp the gap between a `ToolUse` frame arriving and its `ToolResult` arriving: that measures transport and model latency, not the tool, and a number that looks like a duration but is not one is worse than no number. If that observation is ever wanted it gets its own name.

**A backend that cannot populate a field leaves it absent.** Absent means "this backend did not record it", never zero, never a reconstruction from what aikit sent. In particular the snapshot's `system_prompt` is what the model was given, not the prompt aikit passed on the command line; a backend that adds its own prompt around the user's and does not expose the result leaves the field empty.

**The eval trace also learns the in-process text frames.** `AikitTextFinal` and `AikitTextDelta` become `message` lines (`role: assistant`, `kind: message`, `phase: final`/`delta`), so an aikit run's final answer can be found the same way a claude run's is. This was a gap the analysis missed, and it is the smallest change that makes the snapshot test below show a readable trace.

**ADR 0020 binds all of it.** Every new field carries `#[serde(default)]`; every new payload is a new variant; nothing is renamed or removed; `phase` and `action` are recorded on `trace.jsonl` as strings, following `role`, `kind` and `phase` on `message`. The check haystack blanks the snapshot's prompt, tools and skills and every hook's payload, for the reason `Unknown.raw` is blanked: a pattern check must read what the agent did, not what the harness told it.

## Consequences

- `RunOptions`, `AgentConfig`, `AgentInternalEvent`, `Decoded`, `AgentEventPayload` and `TracePayload` all grow. Exhaustive matches on `Decoded` and on `AgentInternalEvent` inside the workspace gain arms; the `#[non_exhaustive]` enums cost external consumers nothing.
- A trial's `trace.jsonl` written with `capture_harness` on begins with one `harness_snapshot` line. A trial written without it is byte-identical to one written before this change, apart from the new `message` lines an aikit run now gets and the `hook` line a compression now gets instead of `unknown`. Fixtures recorded by external backends do not move.
- The per-backend table is honest and uneven. `aikit` populates every field; `pi` could populate the snapshot and a compaction hook and does not yet; `claude`, `codex`, `gemini`, `cursor` and `opencode` leave the snapshot absent and their tool results undated. A consumer that wants long-step detection across backends does not get it from this ADR; it gets a clear "not recorded" instead of a guess.
- The sub-agent gap is recorded, not closed. Emitting a sub-agent's nested frames under its own id is the next step for the reference loop's nested message lists, and it is a change to `SpawnSubagentTool`, not to this vocabulary.
- `hooks` in the snapshot is the list of interventions the harness *may* make, so a reader can tell "no hook fired" from "this harness has no hooks". A hook that fires and changes nothing is still recorded, as `observed`.
